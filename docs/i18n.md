# Internationalization (i18n)

This project localizes **user-facing API messages** with GNU gettext (`.po` / `.mo`)
and FastAPI dependency injection.

## Request flow

```text
HTTP request
    ↓
language detection   (?lang=…  or  Accept-Language)
    ↓
FastAPI DI           get_language → get_translator
    ↓
Translator           translator("expense_not_found")
    ↓
compiled .mo file
    ↓
translated response / error detail
```

## Language detection

Supported languages: **`en`** (default), **`fa`**.

| Source | Example | Priority |
|--------|---------|----------|
| Query parameter | `GET /welcome?lang=fa` | Highest |
| `Accept-Language` header | `Accept-Language: fa` | Used if no `lang` |
| Fallback | — | English (`en`) |

Rules:

1. If `?lang=` is present and supported → use it.
2. Else if `Accept-Language` is present and supported → use it.
3. Else → English.
4. Unsupported values (e.g. `?lang=de`) → English.
5. Locale forms are normalized: `fa-IR` → `fa`, `en-US` → `en`.
   For a header like `fa-IR,en;q=0.9`, only the **first** tag is considered.

Implementation: `app/core/i18n/dependencies.py`.

## Translation files

```text
app/core/i18n/locales/
├── en/LC_MESSAGES/
│   ├── messages.po   # editable source
│   └── messages.mo   # compiled binary (used at runtime)
└── fa/LC_MESSAGES/
    ├── messages.po
    └── messages.mo
```

### `.po` vs `.mo`

| File | Role |
|------|------|
| **`.po`** (Portable Object) | Human-editable source. Contains `msgid` keys and `msgstr` translations. |
| **`.mo`** (Machine Object) | Binary catalog compiled from `.po`. Loaded at runtime by `gettext`. |

Edit `.po` files; always recompile to `.mo` before running the app.

## Translation service

`app/core/i18n/translator.py`:

- Loads the correct `.mo` for a language
- Falls back to the default language when unsupported
- Exposes `Translator` as a callable: `translator("welcome")`
- Caches loaded catalogs with `@lru_cache` so the `.mo` is not re-read on every request

## FastAPI dependency injection

```python
from fastapi import Depends
from app.core.i18n import Translator, get_translator

@app.get("/welcome")
def welcome(translator: Translator = Depends(get_translator)):
    return {"message": translator("welcome")}
```

Language is resolved once per request via `get_language`, then `get_translator`
builds a `Translator` for that language.

## How to test languages

```bash
# Default → English
curl http://127.0.0.1:8000/welcome

# Query parameter → Persian
curl 'http://127.0.0.1:8000/welcome?lang=fa'

# Header → Persian
curl -H 'Accept-Language: fa' http://127.0.0.1:8000/welcome

# Query wins over header → Persian
curl -H 'Accept-Language: en' 'http://127.0.0.1:8000/welcome?lang=fa'

# Locale normalization → Persian
curl -H 'Accept-Language: fa-IR' http://127.0.0.1:8000/welcome

# Unsupported → English
curl 'http://127.0.0.1:8000/welcome?lang=de'
```

Expense example (after login):

```bash
# 404 in Persian
curl -b cookies.txt 'http://127.0.0.1:8000/expenses/999?lang=fa'
```

## How to add a new translation key

1. Add the key to **every** language `.po` file:

```po
msgid "expense_deleted"
msgstr "Expense deleted successfully."
```

Persian:

```po
msgid "expense_deleted"
msgstr "هزینه با موفقیت حذف شد."
```

2. Recompile:

```bash
pybabel compile -d app/core/i18n/locales -D messages
```

3. Use it in code:

```python
translator("expense_deleted")
```

4. Restart the app (or clear the process) so `lru_cache` picks up new `.mo` files
   if catalogs were already loaded.

## How to add a new language (example: Arabic)

1. Create the folder:

```text
app/core/i18n/locales/ar/LC_MESSAGES/messages.po
```

2. Copy keys from `en/LC_MESSAGES/messages.po` and fill in Arabic `msgstr` values.

3. Register the language in `app/core/i18n/translator.py`:

```python
SUPPORTED_LANGUAGES = frozenset({"en", "fa", "ar"})
```

4. Compile:

```bash
pybabel compile -d app/core/i18n/locales -D messages
```

5. Test:

```bash
curl 'http://127.0.0.1:8000/welcome?lang=ar'
```

## Compile command

From the project root (venv activated):

```bash
pybabel compile -d app/core/i18n/locales -D messages
```

Requires the `Babel` package (`pip install Babel`).

## What is / is not translated

Translated:

- Success messages (`logged_in`, `expense_created`, …)
- Error details (`expense_not_found`, `invalid_credentials`, …)
- Demo `/welcome` message

Not translated:

- Database values (expense descriptions, emails)
- Field names / JSON keys (`id`, `amount`, …)
- Technical identifiers and tokens
